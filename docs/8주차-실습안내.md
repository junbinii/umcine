# 8주차 즐겨찾기와 영화 기록

기존 Spring Boot 프로젝트의 7주차 JWT 인증을 사용합니다.

## 실행과 Postman

1. 프로젝트 폴더에서 `./Start-Backend.ps1`을 실행합니다. 이미 서버가 실행 중이면 해당 서버를 종료한 뒤 다시 실행하여 변경 코드를 적용합니다.
2. Postman에서 `postman/week8-favorites.postman_collection.json`을 가져옵니다.
3. 7주차 로그인 API로 받은 토큰을 컬렉션 변수 `accessToken`에 입력합니다. Bearer 접두사는 붙이지 않습니다.
4. `favoriteMovieId`, `recordMovieId`를 해당 회원이 평점과 즐겨찾기를 등록하지 않은 서로 다른 영화 ID로 지정합니다.
5. 01~10 요청을 순서대로 실행합니다. 재실행할 때는 새로운 영화 ID를 사용합니다.

등록·중복·목록·여부·해제 응답과 영화 기록 성공 응답을 캡처하여 제출합니다. 07 요청 후 해당 회원의 평점 목록에서 favoriteMovieId의 평점이 없는지 확인하면 롤백을 검증할 수 있습니다.

## 구현

- Favorite는 BaseTimeEntity를 상속하고 회원과 TMDB movieId를 저장합니다.
- 회원 ID는 토큰에서 가져오며 요청 DTO에는 포함하지 않습니다.
- 등록 전 중복 검사를 수행하고 DB의 복합 UNIQUE 제약으로 동시 중복 요청도 방지합니다. 이름이 지정된 중복 제약 오류는 각 도메인의 409 코드로 변환합니다.
- 목록은 favoriteId 내림차순이며 조회와 해제 모두 로그인한 회원으로 범위를 제한합니다.
- MovieRecordService.create의 @Transactional 안에서 기존 RatingService와 FavoriteService를 호출합니다. 기본 REQUIRED 전파로 두 저장이 같은 트랜잭션에 참여합니다.
- addToFavorites가 false면 평점만 저장하고 favorite는 null입니다. true이면 즐겨찾기까지 저장하며 실패 시 평점도 롤백합니다.

## 검증

`./Test-Backend.ps1`로 기존 테스트와 Week8IntegrationTest 및 bootJar 빌드를 실행합니다.

Week8IntegrationTest는 로컬 MySQL에서 테스트 전용 회원을 만들고 종료 시 그 회원의 데이터를 정리합니다. 회원별 격리, 최신순 조회, 중복·인증·입력 오류, 등록과 해제, 영화 기록 성공, 평점만 저장, 즐겨찾기 중복 후 평점 롤백을 검증합니다. 테스트 자체에는 @Transactional을 적용하지 않아 요청이 끝난 뒤 실제 DB 상태를 검사합니다.

## 핵심 키워드

- 트랜잭션은 여러 DB 작업을 하나의 단위로 묶어 함께 성공하거나 함께 취소되도록 처리하는 것입니다.
- commit은 트랜잭션의 변경을 확정하고 rollback은 실패한 트랜잭션의 변경을 취소합니다.
- 원자성은 트랜잭션 안의 작업이 전부 반영되거나 전부 반영되지 않는 성질입니다.
- ACID는 원자성·일관성·격리성·지속성으로, 트랜잭션이 신뢰할 수 있는 처리를 제공하기 위한 네 가지 성질입니다.
- UNIQUE 제약은 지정한 컬럼 또는 컬럼 조합의 중복을 DB에서 막습니다. 여기서는 회원 ID와 영화 ID의 조합을 사용합니다.
- 낙관적 잠금은 버전 등을 비교하여 다른 요청이 먼저 수정했는지 확인하고 충돌 시 수정을 실패시키는 방식입니다.

## 학습 후기 질문

1. 평점만 저장되면 사용자가 요청한 평점과 즐겨찾기의 동시 저장이 일부만 반영됩니다. 트랜잭션으로 두 작업을 묶으면 실패 시 함께 취소할 수 있습니다.
2. 서버의 사전 검사는 이해하기 쉬운 오류를 제공하고, DB UNIQUE 제약은 동시에 들어와 사전 검사를 모두 통과한 요청의 중복까지 막습니다.

선택 미션인 Swagger 적용과 제출용 화면 캡처는 별도 진행 항목입니다.
